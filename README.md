# 텃씨노트 (TeotssiNote) — 웹앱 프로토타입

학교 재학 여부와 무관하게 참여할 수 있는 청소년 환경교육 프로젝트 텃씨노트의 **첫 번째 작동 가능한 웹앱**입니다. 기존 실물 텃씨노트와 함께 사용하도록 설계했으며, 식물·숲 관찰, 학습, 비교 탐구의 기본 흐름을 담았습니다.

## 바로 실행하기

- `index.html` 파일을 브라우저로 열면 됩니다. 같은 폴더 안에 `styles.css`, `storage.js`, `app.js`가 있어야 합니다.
- GitHub Pages에 배포할 때는 네 파일을 **동일한 저장소 루트**에 올리고 Settings → Pages → Deploy from a branch에서 main / root를 선택합니다. (GitHub Pages의 배포 세부 절차는 계정·설정에 따라 달라질 수 있습니다.)
- 별도 패키지 설치, 빌드, 유료 API 키가 필요하지 않습니다.

## v0.2 변경 사항 — 생활권 중심 장소 선택

- 식물 재배 장소는 **집 안(실내) / 집 베란다·마당 / 거주 지역의 텃밭·정원 / 기타 허용된 재배 장소** 중 선택합니다.
- 숲 관찰 장소는 **자택 인근 숲 / 거주 지역의 공원·녹지 / 거주 지역의 산책로·하천변 / 기타 안전한 관찰 장소** 중 선택합니다.
- 학교 재학생이나 학교 밖 청소년 모두 생활권에서 관찰 가능한 공간을 등록할 수 있습니다.
- 장소는 범주와 사용자가 입력하는 별명으로 저장하며, 정확한 주소·GPS는 수집하지 않습니다.
- 과거 버전에서 `학교 재배 공간`으로 저장한 기록은 삭제하지 않고 편집 시 기존 값도 선택지에 유지되도록 처리했습니다.

## 구현된 기능

- 반응형 홈·모바일 하단 메뉴·첫 관찰 안내
- 식물 등록·정보 수정·삭제, 관찰 날짜·상태·사진·메모 저장·삭제
- 식물 사진 두 시점 비교
- 주변 숲 관찰 장소 등록·삭제, 사진·메모 저장·삭제
- **숲의 시간** 기관 기록 시연(자체 제작된 **가상 삽화** 3개) 및 내 사진과 비교
- 비교 탐구 메모 작성·삭제
- 산림의 회복/맹아/토양 종자은행/천이/복원 방식 학습 카드
- 간단한 선택형 탐구 문제
- 백년숲 '안부숲' 캠페인 외부 링크
- 친구 코드 시연 (`TSS-DEMO`) — **가상 친구 데이터일 뿐 실제 공유가 아님**
- 전체 기록 JSON 내보내기·가져오기·삭제

## 구현 전 기능 및 중요한 한계

- Google 로그인, **기기 간 자동 동기화**, 실제 친구 코드 공유는 **아직 구현되지 않았습니다**.
- 저장 방식은 현재 IndexedDB(대체 localStorage)로서 **동일 브라우저·기기 내부**에 저장됩니다.
- 실사용자의 사진은 서버로 업로드되지 않으며 다른 사용자에게 공유되지 않습니다.
- '기관 관찰 기록'은 실제 산불 피해지나 설치 카메라의 사진이 아닙니다. 운영 방식 시연을 위해 그린 **가상 숲 삽화**입니다.
- 고정 카메라 설치·지자체 협력은 아직 확정되지 않았습니다. 프로토타입에서 관련 관계를 실제 계약처럼 표현하지 않습니다.
- 실제 산림·종자 교육 정보는 종별·지역별 검토 후 추가해야 합니다.
- **브라우저 저장소는 장기 보관의 보증 수단이 아닙니다.** 중요한 기록은 설정에서 JSON 백업을 내려받으세요.

## 클라우드 연동 계획: 같은 웹앱에 추가

`storage.js`가 브라우저 저장용 어댑터입니다. 앱의 나머지 코드는 `TeotStorage.load()` / `TeotStorage.save()`를 통해 기록을 이용합니다.

향후 Supabase를 연결할 때 이 저장 기능을 계정 기반 데이터 연동으로 교체하고, 인증·사진 Storage·친구 관계 권한을 추가합니다. **새 앱을 다시 만드는 것이 아니라 현재 코드에 기능을 확장하는 방식**입니다. 전체 데이터를 하나의 JSON으로 저장하는 지금의 구조는 시연 목적이며, 실제 다중 사용자 서비스에서는 테이블별 데이터 구조와 접근 권한 정책을 설계해야 합니다.

Supabase 프로젝트 생성, Google OAuth 설정, Storage 권한, RLS 정책, 환경변수는 **아직 연결하지 않았습니다**. 서비스 키를 웹 브라우저에 노출하지 마세요. 공개 가능한 anon/publishable key 역시 적절한 데이터 접근 정책과 함께 사용해야 합니다.
